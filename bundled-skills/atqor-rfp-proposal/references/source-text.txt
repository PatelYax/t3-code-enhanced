3. Project Objective
To develop an intelligent, AI-powered chat bot that enables seamless interaction between user and
their operational data by integrating production and profitability related data from SAP and worker
data from HR app. The objective is to empower the management users with context-aware responses
to their queries through a conversational AI agent such as profitability and the influence of various
factors for any variation in profitability as compared to the budgeted values or in comparison with
earlier months etc. This solution aims to enhance decision-making, improve operational
transparency, and reduce the time and effort required to extract insights from complex datasets.
4. Proposed Scope
Functional Scope of work
User Access and Security
• Users will log in to the platform using their company credentials.
• Access to different parts of the solution will be controlled based on the user's role.
Data Structure and Organization
• Design how data is organized and connected to reflect real business needs in areas like HR, Production,
Machine Downtime, and Profitability.
• Ensure the data setup supports fast and accurate information retrieval.
• Make sure the data structure helps the AI understand and respond to user questions correctly.
AI-Powered Assistance
• Use AI to understand user questions and figure out which business area they relate to.
• AI will use a mix of pre-built and custom rules to create accurate answers from the data.
• Answers can be shown as plain text, tables, or charts, depending on what the user prefers.
Chat-Based User Interface
• Web-based platform with both chat and voice capabilities, allowing users to log in and ask questions
through either interface.
• The Solution will direct each question to the right AI helper based on the topic and preferred answer
format.
• Users will see answers in a clear and interactive way—either as text, tables, or visual charts.

Conversation and Session Tracking
• Keep a record of all user chats to help personalize future interactions and improve the solution.
• Store session details so users can continue where they left off, even if they return later.
Technical Scope of work
Platform Authentication via Entra ID:
• Users sign in to the Azure Web App using Entra ID for secure authentication and RBAC enforcement.
Data Modelling:
• Define and optimize the logical and physical data models for on-premises SQL warehouse to ensure
efficient query performance, high data integrity, and clear relationships among tables and entities.
• Validate that schema designs align with business requirements for HRMS, Production, Spinning,
Stoppages & Profitability modules.
• Perform initial schema and table relationship analysis to support the AI Agents’ semantic understanding
(e.g., for query generation).
AI Agents & Orchestration: Use Semantic Kernel as an AI orchestrator to enable multi-agent
solutions:
• The Table Identification Agent and SQL to NLP Agent interpret user queries and map them to the correct
domain (HRMS, Production, Spinning, Stoppages & Profitability), as well as functional logic.
• Considered 30 views of SAP and that will store it as Physical table into synapse data warehouse and upon
that generate SQL Query via AI.
• Considered 40 custom functional logic (Arithmetic Logic).
• The Text-Based, Tabular-Based, and Graph-Based Response Formation Agents finalize the user-facing
answer in the requested format (e.g., text summary, interactive table, or chart-ready data).
Chat Interaction & Web App:
• Provide a web-based chat interface where Entra ID–authenticated users submit questions.
• Route user queries to the appropriate AI Agent(s) based on domain (HRMS, Production, Spinning,
Stoppages & Profitability) and requested response type (text, table, or graph).
• Display chat results in multiple formats: text-based answers, tabular data, or graph-based visualizations.
• Voice-based input needs to be developed as part of chat interaction.
Chat History Management:
• Maintain conversation logs in Cosmos DB for personalization, context retention, and analytics.
• Implement session management using a persistent store called Cosmos DB.

Profitability) are well-defined and finalized before development begins.

4. Hypercare Support
The Hypercare support is provided from the go-live date until the next thirty calendar days. This phase, also
known as "Post go-live support," aims to optimize solution usage by assisting end users with their queries.
During this period, no development work will be carried out except for addressing production or data-related
bugs. If any issues are identified during this time that were missed during user acceptance testing (UAT), they
will be addressed through the change management process. The purpose of this support is to provide
assistance in querying and troubleshooting production issues to stabilize the process. Following the
Hypercare period, the project will transition into a regular support model or the Application Maintenance
Service (AMS) – this is optional and not required to be purchased along with this proposal.
