Executive Summary
This project aims to deliver a production-ready AI ERP Agent that facilitates natural language queries
against read-only SAP sales data, including master data, primary sales actuals, and sales planning
targets stored in Microsoft Fabric. As part of this effort, a new data pipeline will be established to
fetch data from the Silver Layer to Gold Layer in Microsoft Fabric, incorporating necessary calculations
and aggregations currently absent in the source views.
The AI ERP Agent (deployed as a Microsoft Teams chatbot) will enable users to:
• Query Product Master Data Instantly — Access SKU attributes, material hierarchies (MG1-
MG5), gross weight, UOM, and material group classifications through natural language
questions without navigating SAP transactions.
• Access Customer Intelligence On-Demand — Retrieve customer profiles, GST/PAN details,
territory assignments (Zone/State/SubZone, ASM/SO/SR), credit limits, and outstanding
amounts conversationally.
• Analyse Primary Sales Performance in Natural Language — Get instant insights on actual
sales by quantity, value, discounts, and taxes across dimensions like material, customer, plant,
distribution channel, and time periods.
• Compare Plan vs. Actual Achievement — Measure sales performance against AOP and
monthly plan targets by common dimensions (plant, distribution channel, month) to track
achievement percentages and variances.
In addition to single-question capabilities, the AI ERP Agent will handle follow-up queries, maintaining
conversation context for incremental refinements without requiring users to restate all details.
Supported Business (Process) Domains:
• Material / Product Master Inquiry – Material master attributes, material group, MG14–MG18
hierarchy, weight/UOM, size/UPC-like field, etc.
• Customer Master Inquiry – Customer master + sales area + GST/PAN + zone/state/subzone +
credit/outstanding fields
• Distribution Channel – distribution channel codes and enable channel-based filtering.
• Primary Sales (Actuals) – Analyze actual sales (qty, value, discount, taxes) by
invoice/material/customer/plant/channel/date.
• Tax & Compliance from Sales (GST / HSN / E-Way) – HSN, CGST/SGST/IGST % + amounts,
EWayBill/EWayDate.
• Pricing / Discount / MRP Performance (Sales-derived) – Analyze SellPrice/InvoiceRate/MRP
and discount fields from the sales fact.
• Sales Planning – Annual Operating Plan (AOP) Target Query – AOP targets
(TotalSalesValuePrice, TotalQtyCV) by Year/Month, Zone/SubZone/State,
DistributionChannel, PlantCode, EtprCode, SaleType.

Multi-Agent Orchestration & Query Handling
• Intent Classifier Agent
Purpose: The Intent Agent serves as the gateway classifier that analyzes user queries in
natural language and determines the business domain, process type, and intent to route the
request appropriately through the system.
How It Works
o Receives the raw user query in natural language and parses it to understand the core
intent
o Classifies the query into predefined business domains/categories (e.g., Production,
Sales, Quality, Inventory)
o Extracts multiple sub-questions if the user query contains compound requests
o Returns a structured JSON response with classified questions and their associated
process types for further processing

• Functional Logic Agent
Purpose: The Functional Logic Agent acts as the business intelligence layer that maps user
questions to the appropriate business rules, formulas, KPIs, and calculation logic required to
answer the query.
How It Works
o Performs semantic search against a knowledge base of pre-defined business
calculations and formulas
o Identifies the relevant metrics, KPIs, and business logic associated with the user's
question
o Resolves dependencies between calculations (e.g., "Efficiency requires both Actual
Output and Target Output")
o Returns structured information including description, formula, required tables,
lookup logic, and dependency mappings
o Handles complex hierarchical calculations by identifying parent-child task
relationships
• Metadata Logic Agent
Purpose: The Metadata Logic Agent functions as the data dictionary resolver that translates
business concepts and formulas into specific database schema elements including tables,
columns, and data access patterns.
How It Works
o Searches the metadata repository to identify the exact tables and columns where
required data resides
o Validates that all required columns exist and are accessible for the requested query
o Returns enriched task details with precise table names, column lists, and refined
lookup logic
• NLP-SQL/ NL Agent
Purpose: The NLP-SQL Agent serves as the query generation and execution engine that
constructs valid SQL queries from the enriched metadata, executes them against the
database, and translates raw results into meaningful natural language responses.
How It Works
o Receives enriched task information including tables, columns, formulas, and lookup
logic from upstream agents
o Generates syntactically correct T-SQL queries compatible with the target database

o Applies proper filtering, grouping, aggregation, and sorting based on the business
logic requirements
o Executes the generated SQL queries against the database and retrieves result sets
o Handles parent-child task execution where child task results feed into parent
calculations
o Interprets raw data and formulates human-readable answers explaining the results
o Maintains query history and execution data for audit and visualization purposes
• Graph Agent
Purpose: The Graph Agent functions as the data visualization recommender that analyzes
query results and determines the optimal chart type, data structure, and visual
representation for presenting insights to end users.
How It Works
o Analyzes the structure and nature of the data returned from SQL query execution
o Determines the most suitable visualization type based on data characteristics (bar
chart, line graph, pie chart etc.)
o Identifies meaningful comparisons, trends, or distributions that should be highlighted
visually
o Handles multiple result sets by generating appropriate visualization configurations
for each
• Follow-up / Context-Aware Agent
Purpose: The Follow-up Agent acts as the conversational memory layer that ensures users
provide all necessary information before query processing, while also remembering what
was discussed earlier to avoid repetitive questions.
How It Works
o Maintains awareness of the ongoing conversation and remembers previous
questions, answers, and parameters shared by the user
o Identifies when a user query is incomplete or missing required details
o Automatically retrieves missing information from earlier conversation turns if the
user already mentioned it before
o Generates intelligent follow-up questions when essential details are not available in
the current query or conversation history

Success and Acceptance Criteria
Success Criteria
The following success criteria will be finalized during the initial kick-off call with HRIPL team:
• Query Success Rate: ≥ 90% of user queries are successfully translated to SQL and return
correct results (measured during UAT and first month post-go-live)
• Response Time: ≥ 90% of queries return results within 30 seconds (excluding complex
aggregations or large result sets)
• Context Accuracy: ≥ 85% of follow-up queries correctly interpret conversational context
without requiring the user to restate information
• Calculation Accuracy: 100% of calculations in Gold Layer match business requirements
(validated during UAT by Finance team)
• Availability: ≥ 99% uptime during business hours (excluding planned maintenance)
Acceptance Criteria
The project will be considered complete and ready for production go-live when:
• All 9 business domains are implemented and tested:
o Material / Product Master Inquiry
o Customer Master Inquiry
o Distribution Channel
o Primary Sales (Actuals)
o Tax & Compliance from Sales
o Pricing / Discount / MRP Performance (Sales-derived)
o Sales Planning – (AOP) Target Query
o Sales Planning – Monthly Plan Target Query
o Plan vs Actual (Achievement / Variance)
• Gold Layer pipeline is deployed and running on schedule (daily/weekly refresh)
• UAT is successfully completed with sign-off from Finance and Operations teams:
o All test cases passed (≥90% success rate)
o No critical or high-priority bugs outstanding
• Contextual chat and follow-up queries are working as expected (validated in UAT)
